# ChatGPT Desktop на VPS через браузер

Этот проект автоматически устанавливает **ChatGPT Desktop на VPS с Ubuntu 24.04** и позволяет пользоваться им через обычный браузер.

После установки вы сможете открыть адрес вроде:

```text
https://chat.example.com
```

и получить удалённый графический рабочий стол с:

- ChatGPT Desktop;
- браузером Falkon для входа в аккаунт;
- терминалом;
- лёгким графическим окружением Openbox;
- буфером обмена;
- HTTPS-защитой;
- отдельным VNC-паролем.

Полноценный Ubuntu Desktop устанавливать не требуется.

---

# Для кого этот проект

Проект рассчитан на обычных пользователей, которые:

- арендуют VPS;
- умеют подключиться к нему по SSH;
- имеют домен или готовы его купить;
- хотят пользоваться ChatGPT Desktop на удалённом сервере;
- не хотят вручную настраивать Linux-графику, VNC, HTTPS и systemd.

Знание программирования не требуется.

---

# Как это работает

На обычном VPS нет физического монитора.

Поэтому скрипт создаёт виртуальный экран и передаёт его в браузер.

Схема выглядит так:

```text
ChatGPT Desktop
       ↓
    Openbox
       ↓
      Xvfb
       ↓
     x11vnc
       ↓
      noVNC
       ↓
      Caddy
       ↓
 HTTPS + браузер
```

### Xvfb

Создаёт виртуальный монитор на VPS.

### Openbox

Лёгкое графическое окружение.

В нём запускаются ChatGPT Desktop, Falkon и Terminal.

### Falkon

Лёгкий браузер.

Он нужен в основном для входа в аккаунт ChatGPT.

Когда ChatGPT Desktop открывает страницу авторизации, она появляется в Falkon.

### x11vnc

Передаёт изображение виртуального экрана через VNC.

### noVNC

Позволяет пользоваться VNC непосредственно в обычном веб-браузере.

Устанавливать отдельную VNC-программу на компьютер не нужно.

### Caddy

Публикует noVNC через HTTPS.

Также Caddy автоматически получает SSL/TLS-сертификат для вашего домена.

### autocutsel

Помогает синхронизировать буфер обмена внутри графической X11-сессии.

# Требования

Для установки понадобится:

- VPS;
- Ubuntu **24.04**;
- архитектура **amd64 / x86_64**;
- root-доступ к VPS;
- публичный IPv4;
- домен или поддомен;

# Часть 1. Как получить домен

Если домен у вас уже есть, переходите к разделу:

**Как создать поддомен**

Если домена нет, его нужно зарегистрировать у любого регистратора доменных имён.

Например, вам нужен адрес:

```text
example.com
```

или:

```text
myserver.ru
```

После покупки домена вы получите доступ к панели управления DNS.

Важно понимать:

**домен не создаётся на VPS.**

VPS и домен — это две отдельные вещи.

VPS имеет IP-адрес, например:

```text
203.0.113.10
```

Домен — это удобное имя:

```text
example.com
```

DNS связывает их между собой.

---

# Лучше использовать поддомен

Не рекомендуется отдавать весь основной домен только под ChatGPT.

Например, если у вас есть:

```text
example.com
```

лучше создать:

```text
chat.example.com
```

Именно этот адрес затем будет использовать скрипт.

Другие варианты:

```text
gpt.example.com
desktop.example.com
ai.example.com
workspace.example.com
```

Название можно выбрать любое.

# Часть 2. Узнаём IP вашего VPS

Он выглядит примерно так:

```text
203.0.113.10
```

Также после подключения к VPS можно выполнить:


Например:

```text
203.0.113.10
```

Запомните его.

# Часть 3. Как настроить DNS

Откройте панель управления вашим доменом.

Найдите раздел с названием вроде:

```text
DNS
DNS Records
DNS Management
Zone Editor
Управление DNS
DNS-записи
Редактор зоны
```

Нужно создать **A-запись**.

---

## Пример

Допустим:

ваш домен:

```text
example.com
```

IP вашего VPS:

```text
203.0.113.10
```

Вы хотите использовать:

```text
chat.example.com
```

Создайте запись:

| Поле | Значение |
|---|---|
| Type / Тип | A |
| Name / Host | chat |
| Value / Address | 203.0.113.10 |
| TTL | Auto или 300 |

Получится:

```text
chat.example.com → 203.0.113.10
```

---

# Что писать в поле Name / Host

Это зависит от панели регистратора.

Если нужен адрес:

```text
chat.example.com
```

обычно в поле `Name` пишется только:

```text
chat
```

Не нужно писать:

```text
https://chat.example.com
```

Не нужно писать:

```text
http://chat.example.com
```

Не нужно писать:

```text
chat.example.com/vnc.html
```

Нужно только:

```text
chat
```

---

# Что писать в поле Value / Address

Туда записывается публичный IPv4 VPS.

Например:

```text
203.0.113.10
```

Не указывайте:

```text
https://203.0.113.10
```

Нужен только IP.

---

# Что выбрать в TTL

Если вы не знаете, что это такое, оставьте:

```text
Auto
```

или:

```text
300
```

или стандартное значение вашего регистратора.

Это не критично.

---

# Если используется Cloudflare

Если DNS вашего домена управляется через Cloudflare, создайте A-запись аналогично:

```text
Type: A
Name: chat
IPv4 address: IP вашего VPS
```

Для первоначальной установки проще использовать режим:

```text
DNS only
```

То есть серое облако.

После того как всё заработает, настройки Cloudflare можно менять отдельно, если вы понимаете, зачем это требуется.

# Как проверить DNS

После создания A-записи подождите немного.

Обычно изменения появляются быстро, но иногда распространение DNS занимает больше времени.

На VPS выполните:

```bash
getent ahostsv4 chat.example.com
```

Разумеется, замените:

```text
chat.example.com
```

на свой домен.

Вы должны увидеть IP вашего VPS.

Например:

```text
203.0.113.10
```

---

## Ещё одна проверка

Можно выполнить:

```bash
ping -c 1 chat.example.com
```

В выводе должен фигурировать IP вашего VPS.

Сам установщик тоже проверяет DNS и остановится, если домен направлен на другой сервер.

# Зачем установлен Falkon

ChatGPT Desktop использует системный браузер для входа в аккаунт.

На минимальной Ubuntu браузера обычно вообще нет.

Поэтому установщик автоматически устанавливает лёгкий браузер Falkon и назначает его браузером по умолчанию.

Без браузера кнопка входа в ChatGPT могла бы внешне ничего не делать.

# Буфер обмена

В последней версии установщика добавлена синхронизация X11-буфера через `autocutsel`.

Для обычного текста копирование и вставка между приложениями внутри рабочего стола должны работать значительно лучше.

# Буфер между вашим компьютером и VPS

noVNC также имеет собственную функцию Clipboard.

Обычно она находится в боковой панели noVNC.

Если обычные:

```text

Ctrl+V
```

между вашим компьютером и удалённым рабочим столом работают неидеально, используйте кнопку:

```text
Clipboard
```

в панели noVNC.

Это особенно полезно для вставки длинного текста.

# Порты

| Порт | Что это | Доступ |
|---|---|---|
| 22 или ваш SSH-порт | SSH | интернет |
| 80 | HTTP / HTTPS redirect | интернет |
| 443 | HTTPS | интернет |
| 5900 | VNC | localhost |
| 6080 | noVNC | localhost |

Порты:

```text
5900
6080
```

не должны быть публично открыты.

Caddy получает доступ к noVNC локально внутри VPS.

# Безопасность

Удалённый рабочий стол фактически даёт доступ к вашей пользовательской сессии.

Поэтому:

- используйте сложный Caddy-пароль;
- используйте сложный VNC-пароль;
- не открывайте порт 5900 в интернет;
- не открывайте порт 6080 в интернет;
- не публикуйте пароли в GitHub;
- не публикуйте приватные ключи;
- периодически обновляйте Ubuntu;
- используйте VPS в надёжном дата-центре.

---

# Обновление Ubuntu

Периодически:

```bash
apt update
apt upgrade -y
```

Если система сообщает, что установлено новое ядро, рекомендуется:

```bash
reboot
```

---

# Если VPS перенесён на другой IP

После переноса VPS может измениться IP.

Тогда нужно изменить A-запись DNS.

Например раньше было:

```text
chat.example.com → 203.0.113.10
```

а новый VPS получил:

```text
198.51.100.25
```

Измените DNS:

```text
chat.example.com → 198.51.100.25
```

После этого проверьте:

```bash
getent ahostsv4 chat.example.com
```

---

# Если VPS переустанавливается

При полной переустановке ОС все данные VPS обычно удаляются.

Перед этим сохраните всё необходимое.

После установки чистой Ubuntu 24.04:

1. проверьте IP;
2. исправьте DNS, если IP изменился;
3. загрузите `install.sh`;
4. выполните:

```bash
bash install.sh
```

5. выберите:

```text
1
```

# Что создаёт скрипт

Конфигурация:

```text
/etc/chatgpt-vps.conf
```

Маркер выполненной установки:

```text
/etc/chatgpt-vps-installed
```

Systemd-сервисы:

```text
/etc/systemd/system/chatgpt-xvfb.service
/etc/systemd/system/chatgpt-desktop.service
/etc/systemd/system/chatgpt-vnc.service
/etc/systemd/system/chatgpt-novnc.service
```

Caddy:

```text
/etc/caddy/Caddyfile
```

Openbox:

```text
/home/workspace/.config/openbox/autostart
```

VNC-пароль:

```text
/home/workspace/.vnc/passwd
```

Лог ChatGPT:

```text
/home/workspace/.local/state/chatgpt-desktop.log
```

# Нужен ли полноценный Ubuntu Desktop?

Нет.

GNOME, KDE Plasma и другие тяжёлые окружения не требуются.

Используется лёгкий Openbox.

---

# Нужен ли монитор?

Нет.

Xvfb создаёт виртуальный монитор программно.

---

# Нужен ли VNC-клиент?

Нет.

Всё открывается непосредственно в браузере через noVNC.

---

# Можно ли закрыть SSH?

Да.

После запуска сервисы работают через systemd.

SSH-окно можно закрыть.

---

# Продолжит ли ChatGPT работать после выхода из SSH?

Да.

Графическая сессия не привязана к открытому SSH-соединению.

---

# Будет ли всё работать после перезагрузки?

Да, если включена автозагрузка.

Её можно включить:

```bash
bash install.sh
```

и выбрать:

```text
2
```

---

# Важное ограничение

Этот проект не превращает ChatGPT в серверное приложение.

Он запускает обычное графическое приложение ChatGPT Desktop внутри виртуального Linux-дисплея.

То есть:

```text
ChatGPT Desktop → виртуальный монитор → VNC → браузер
```

После обновлений Ubuntu, ChatGPT Desktop, Electron, Caddy или noVNC некоторые детали могут измениться.

# Если создаёте Issue на GitHub

Приложите вывод:

```bash
systemctl is-active \
caddy \
chatgpt-xvfb \
chatgpt-desktop \
chatgpt-vnc \
chatgpt-novnc
```

Порты:

```bash
ss -ltnp | grep -E ':80|:443|:5900|:6080'
```

Проверка Caddy:

```bash
caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
```

Логи:

```bash
journalctl -u chatgpt-desktop -n 100 --no-pager
```

```bash
journalctl -u caddy -n 100 --no-pager
```

```bash
tail -n 100 /home/workspace/.local/state/chatgpt-desktop.log
```

Перед публикацией обязательно удалите:

- пароли;
- токены;
- cookies;
- приватные ключи;
- персональные данные.
